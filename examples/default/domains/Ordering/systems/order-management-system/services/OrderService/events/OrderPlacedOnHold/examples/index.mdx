## 1. Hold an order for address verification

Pause an order because the courier could not validate the delivery postcode. Fulfilment stops work, and the customer sees a short message explaining the delay.

### Payload details

- `reason` is `ADDRESS_VERIFICATION`, and `ownerTeam` routes the hold to `ordering-operations`.
- `holdId` identifies this hold; the matching `OrderHoldReleased` event uses the same value.
- `customerMessage` is the text shown to the customer (at most 280 characters).
- `reviewBy` is the deadline for resolving the hold, and `placedAt` records when it started.

### Using this example

Use this to check that fulfilment pauses the order and that customer-facing systems show `customerMessage` as it is.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderPlacedOnHold schema. The package names and publish methods are illustrative.

```javascript publish-order-placed-on-hold.js
import { EventsClient } from '@acme/events';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY,
});

const event = {
  orderId: '4e9d1b7a-8c2f-4a6e-b3d5-1f7c9e2a4b68',
  holdId: 'b2c4e6a8-0d1f-4b3a-9c5e-7d9f1b3a5c70',
  reason: 'ADDRESS_VERIFICATION',
  ownerTeam: 'ordering-operations',
  customerMessage: 'We are checking your delivery address with our courier. No action is needed yet.',
  reviewBy: '2026-09-12T13:00:00Z',
  placedAt: '2026-09-12T09:15:20Z',
};

await client.publish('OrderPlacedOnHold', event);
```

```python publish_order_placed_on_hold.py
  }
```

## 2. Hold an order for fraud review

Pause a large hoodie order flagged by fraud screening. The review is internal, so no customer message is sent.

### Payload details

- `reason` is `FRAUD_REVIEW`, and `ownerTeam` is `payments-risk`.
- `customerMessage` is omitted, so the customer is not told about the review.
- `reviewBy` is four hours after `placedAt`.

### Using this example

Use this to check that customer-facing systems show nothing when `customerMessage` is missing, and that operational tooling escalates the hold if it is still open after `reviewBy`.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderPlacedOnHold schema. The package names and publish methods are illustrative.

</Column>
