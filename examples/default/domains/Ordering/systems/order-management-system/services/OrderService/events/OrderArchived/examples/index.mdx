## 1. Archive a completed order

Archive the bulk order once its operational retention period ends. Because it involved a payment, it is kept as a financial record.

### Payload details

- `terminalStatus` is `COMPLETED`, and `retentionCategory` is `FINANCIAL_RECORD`.
- `archiveReference` is the location of the archived order in long-term storage.
- `recordChecksum` is the lowercase SHA-256 hex digest of the archived record.
- `terminalAt` is when the order was completed, and `archivedAt` is when it moved to the archive.

### Using this example

Use this to check that support and reporting tools switch to reading from `archiveReference`, and verify the file against `recordChecksum` before trusting it.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderArchived schema. The package names and publish methods are illustrative.

import { EventsClient } from '@acme/events';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY,

  orderId: 'c2a6a826-8661-4bc7-aaf7-83fa8e7940d4',

  retentionCategory: 'FINANCIAL_RECORD',
  archiveReference: 'orders/2026/09/c2a6a826-8661-4bc7-aaf7-83fa8e7940d4.json',

};

await client.publish('OrderArchived', event);

## 2. Archive a cancelled order under legal hold

Archive an order that was cancelled because of stock problems and is now part of a customer dispute. The legal hold stops it being deleted at the end of the normal retention period.

### Payload details

- `terminalStatus` is `CANCELLED`, and `retentionCategory` is `LEGAL_HOLD`.
- `terminalAt` matches the time the order was cancelled.
- `archiveReference` and `recordChecksum` are required for every archived order.

### Using this example

Use this to check that retention jobs never delete records in the `LEGAL_HOLD` category, whatever their age.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderArchived schema. The package names and publish methods are illustrative.
