## 1. Start expedited home delivery

Publish when the bulk order of ten T-shirts is released to the London warehouse for picking and packing. Customer communications use the estimated dispatch time to update delivery expectations.

### Payload details

- `fulfilmentId` identifies the warehouse job; `warehouseId` is `wh-london-02`.
- `itemCount` is `10`, one for each T-shirt.
- `priority` is `EXPEDITED` because the customer upgraded to express delivery, and `deliveryMethod` is `HOME_DELIVERY`.
- `estimatedDispatchAt` and `startedAt` are in UTC.

### Using this example

Use this to check that notifications show the estimated dispatch time, and that analytics measure the time from confirmation to `startedAt`.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderFulfilmentStarted schema. The package names and publish methods are illustrative.

## 2. Start standard click and collect

Publish when an order for two T-shirts and a cap is released to the Manchester warehouse for collection in store. The dispatch time is not known yet, so it is left out.

### Payload details

- `deliveryMethod` is `CLICK_AND_COLLECT` and `priority` is `STANDARD`.
- `itemCount` is `3`: two T-shirts and one cap.
- `estimatedDispatchAt` is omitted, because the store transfer has not been scheduled.

### Using this example

Use this to check that consumers send a collection message rather than a delivery message, and do not show a dispatch time when `estimatedDispatchAt` is missing.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderFulfilmentStarted schema. The package names and publish methods are illustrative.
