## 1. Release an address verification hold

Release the address hold automatically once the customer has corrected their postcode and the courier has validated the new address. The order goes back into the fulfilment queue.

### Payload details

- `holdId` matches the hold from `OrderPlacedOnHold`, and `previousReason` is `ADDRESS_VERIFICATION`.
- `releasedBy` identifies the automated address verification policy.
- `nextStatus` is `AWAITING_FULFILMENT`.
- `resolution` records how the concern was resolved, for support and audit.

### Using this example

Use this to check that consumers close the hold with the matching `holdId` and that fulfilment picks the order up again.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderHoldReleased schema. The package names and publish methods are illustrative.

</Column>

```javascript publish-order-hold-released.js
import { EventsClient } from '@acme/events';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY,
});

const event = {
  orderId: '4e9d1b7a-8c2f-4a6e-b3d5-1f7c9e2a4b68',
  holdId: 'b2c4e6a8-0d1f-4b3a-9c5e-7d9f1b3a5c70',
  previousReason: 'ADDRESS_VERIFICATION',
  resolution: 'Customer corrected the postcode and the courier validated the new address',
  releasedBy: 'address-verification-policy:v3',
  nextStatus: 'AWAITING_FULFILMENT',
  releasedAt: '2026-09-12T10:02:48Z',
};

await client.publish('OrderHoldReleased', event);
```

      "releasedAt", "2026-09-12T10:02:48Z"

  }
}

## 2. Release a fraud review hold

Release the fraud hold on the hoodie order after an analyst confirmed the buyer. The hold was placed before confirmation, so the order returns to `CONFIRMED`.

### Payload details

- `previousReason` is `FRAUD_REVIEW`, and `releasedBy` identifies the analyst.
- `nextStatus` is `CONFIRMED`, not `AWAITING_FULFILMENT`.
- `releasedAt` is before the `reviewBy` deadline on the original hold.

### Using this example

Use this to check that consumers move the order to `nextStatus` from the event, rather than assuming every released order goes straight to fulfilment.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderHoldReleased schema. The package names and publish methods are illustrative.

</Column>
