## 1. Publish a price change

Publish an update that only changes the price. The event carries the changed fields, not the whole product, so consumers merge it into their copy.

### Payload details

- `eventId` uniquely identifies this event; `occurredAt` records when the change happened in UTC.
- `productId` identifies the product that changed.
- `changes` contains only the fields that changed. Here the price was reduced to **4,499 pence (£44.99)**.
- `changes.price` uses integer minor units; `changes.currency` is `GBP`.

### Using this example

Use this to check that consumers merge `changes` into their stored product rather than replacing it. Fields not present in `changes`, such as the name and description, must stay as they were.

The examples use a **fictional Acme Events SDK** to publish a payload matching the ProductUpdated schema. The package names and publish methods are illustrative.

```java ProductUpdated.java
import com.acme.events.EventsClient;
import java.util.List;
import java.util.Map;

public class ProductUpdated {
  public static void main(String[] args) {
    var client = new EventsClient(
      System.getenv("ACME_API_KEY")
    );

    client.publish("ProductUpdated", Map.of(
      "eventId", "9e1a8891-9647-62fa-b66d-029ae3ab2c09",
      "occurredAt", "2026-09-11T11:00:00Z",

      "changes", Map.of(
        "price", 4499,
        "currency", "GBP"
      )
    ));
  }
}
```

## 2. Publish a product archived

Publish a status-only change that takes a product off sale.

### Payload details

- `changes` contains a single field, `status`, set to `ARCHIVED`.
- No other product fields are sent, because nothing else changed.

### Using this example

Use this to check that search and storefront consumers remove `ARCHIVED` products. Archiving is reversible: a later update with status `ACTIVE` puts the product back on sale.

The examples use a **fictional Acme Events SDK** to publish a payload matching the ProductUpdated schema. The package names and publish methods are illustrative.

</Column>
