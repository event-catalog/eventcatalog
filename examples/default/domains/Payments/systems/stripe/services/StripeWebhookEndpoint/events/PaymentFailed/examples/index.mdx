## 1. Publish a card declined failure

Publish a failure where the card issuer declined the charge. The customer can retry with another payment method.

### Payload details

- `paymentId` identifies the payment attempt; `orderId` identifies the order it was for.
- `reason` is `CARD_DECLINED`.
- `failedAt` records when the failure happened in UTC.

### Using this example

Use this to check that consumers keep the order open and prompt the customer to retry, rather than cancelling the order.

The examples use a **fictional Acme Events SDK** to publish a payload matching the PaymentFailed schema. The package names and publish methods are illustrative.

</Column>

<Column>

<CodeGroup dropdown>

```javascript payment-failed.js
import { EventsClient } from "@acme/events";

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY,
});

await client.publish("PaymentFailed", {
  paymentId: "c2f1a6e4-2d3b-4c1e-9f8a-7b6c5d4e3f21",
  orderId: "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  reason: "CARD_DECLINED",
  failedAt: "2026-09-11T08:13:02Z",
});
```

```python payment_failed.py
    "orderId": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "reason": "CARD_DECLINED",
    "failedAt": "2026-09-11T08:13:02Z",
})
```

```java PaymentFailed.java
import com.acme.events.EventsClient;
import java.util.List;
import java.util.Map;

public class PaymentFailed {
  public static void main(String[] args) {
    var client = new EventsClient(
      System.getenv("ACME_API_KEY")
    );

    client.publish("PaymentFailed", Map.of(
      "paymentId", "c2f1a6e4-2d3b-4c1e-9f8a-7b6c5d4e3f21",
      "orderId", "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
      "reason", "CARD_DECLINED",
      "failedAt", "2026-09-11T08:13:02Z"
    ));
  }
}
```

```csharp PaymentFailed.cs
    reason = "CARD_DECLINED",

});
```

## 2. Publish a processing error

Publish a failure where the payment processor returned an error unrelated to the card.

### Payload details

- `reason` is `PROCESSING_ERROR`.
- The remaining fields match the card declined example.

### Using this example

Use this to check that consumers treat the failure as retryable on the platform side. The customer should not be asked to act.

The examples use a **fictional Acme Events SDK** to publish a payload matching the PaymentFailed schema. The package names and publish methods are illustrative.

</Column>
