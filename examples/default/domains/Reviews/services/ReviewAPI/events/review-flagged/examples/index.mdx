## 1. Publish the first flag on a review

The Review API has recorded a customer's off-topic report against a navy baseball cap review. It publishes this event so the Review Moderation Worker can screen the review again.

### Payload details

- `reviewId` is the flagged review.
- `productId` is `prod_cap_baseball_navy`, added so consumers do not need to look up the review.
- `reason` is `off_topic`, copied from the `FlagReview` command.
- `flagCount` is `1`, meaning this is the first flag the review has received.
- `flaggedAt` matches the time the flag was raised.

### Using this example

A moderation consumer should queue the review for another screening and decide whether to leave it live or publish `ReviewRejected`.

The examples use a **fictional Acme Events SDK** to publish a payload matching the ReviewFlagged schema. The package names and publish methods are illustrative.

</Column>

```javascript publish-review-flagged.js
import { EventsClient } from '@acme/events';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY,
});

const event = {
  reviewId: 'b2d6f8a1-4c3e-4a9b-9f7d-5e1c3a8b0d24',
  productId: 'prod_cap_baseball_navy',
  reason: 'off_topic',
  flagCount: 1,
  flaggedAt: '2026-09-16T12:40:18Z',
};

await client.publish('ReviewFlagged', event);
```

      "productId", "prod_cap_baseball_navy",
      "reason", "off_topic",
      "flagCount", 1,
      "flaggedAt", "2026-09-16T12:40:18Z"
    );

  }
}

## 2. Publish a repeat abuse flag

A moderator flags a sunset graphic T-shirt review for abuse after two customers have already reported it. The rising `flagCount` tells the moderation worker this review needs urgent attention.

### Payload details

- `productId` is `prod_tshirt_graphic_sunset`.
- `reason` is `abuse`, the reason on the latest flag.
- `flagCount` is `3`: the total number of flags on this review, including this one.
- `flaggedAt` is the time of the latest flag.

### Using this example

Use this payload to test any priority rules, for example that reviews with an `abuse` flag or a high `flagCount` are screened first.

The examples use a **fictional Acme Events SDK** to publish a payload matching the ReviewFlagged schema. The package names and publish methods are illustrative.

</Column>
