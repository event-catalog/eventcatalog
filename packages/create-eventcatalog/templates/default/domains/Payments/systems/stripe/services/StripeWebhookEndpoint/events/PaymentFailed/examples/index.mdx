## 1. Report a declined card

The customer's bank declines the card for a hoodie order. The StripeWebhookEndpoint publishes `PaymentFailed` and the PaymentWorker records the payment as failed, which leads to the order being cancelled.

### Payload details

- `reason` is `CARD_DECLINED`: the issuing bank refused the charge.
- `paymentId` and `orderId` identify the failed payment and its order.
- `failedAt` is when Stripe reported the failure.

### Using this example

Consumers should mark the payment as failed and start cancelling `orderId`. The customer can be asked to try another card.

The examples use a **fictional Acme Events SDK** to publish a payload matching the PaymentFailed schema. The package names and publish methods are illustrative.

</Column>

<Column>

<CodeGroup dropdown>

```typescript publish-payment-failed.ts
import { EventsClient } from '@acme/events';
import type { PaymentFailed } from './schemas/payment-failed';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY!,
});

const event: PaymentFailed = {
  paymentId: '428dc169-43a6-479d-9661-5b07984cb556',
  orderId: '2d7ef31b-211a-4dbc-898a-0b095e7b909c',
  reason: 'CARD_DECLINED',
  failedAt: '2026-09-16T02:47:20Z',
};

await client.publish('PaymentFailed', event);
```


```java PublishPaymentFailed.java
      "reason", "CARD_DECLINED",
```

## 2. Report an expired card

A customer pays for a cap with a saved card that has expired. Stripe rejects the charge and the StripeWebhookEndpoint publishes `PaymentFailed`.

### Payload details

- `reason` is `EXPIRED_CARD`: the card's expiry date has passed.
- This is caused by the customer's card details, so retrying the same card will not help.

### Using this example

Use this payload to check that consumers prompt the customer to update their card rather than retrying.

The examples use a **fictional Acme Events SDK** to publish a payload matching the PaymentFailed schema. The package names and publish methods are illustrative.

## 3. Report a processing error

Stripe has a temporary problem while charging a T-shirt order. The StripeWebhookEndpoint publishes `PaymentFailed` even though the card itself is fine.

### Payload details

- `reason` is `PROCESSING_ERROR`: the failure is on the processor side, not the customer's card.
- This is the only reason in the schema where a retry may succeed.

### Using this example

Use this payload to test retry handling: consumers may retry the charge before cancelling the order.

The examples use a **fictional Acme Events SDK** to publish a payload matching the PaymentFailed schema. The package names and publish methods are illustrative.

</Column>
