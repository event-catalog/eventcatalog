## 1. Publish a customer-requested cancellation

The Order Service has handled a `CancelOrder` command from the customer's account page. It publishes this event so inventory, payments and fulfilment can undo their work.

### Payload details

- `orderId` is the cancelled order.
- `customerId` is included, so notification services can send a cancellation email.
- `reason` is `CUSTOMER_REQUESTED`.
- `cancelledAt` is the ISO-8601 UTC time the cancellation was recorded.

### Using this example

Consumers should release the stock, void the payment authorisation and confirm the cancellation to the customer.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderCancelled schema. The package names and publish methods are illustrative.

</Column>

<Column>

<CodeGroup dropdown>

```typescript publish-order-cancelled.ts
import { EventsClient } from '@acme/events';
import type { OrderCancelled } from './schemas/order-cancelled';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY!,
});

const event: OrderCancelled = {
  orderId: 'e3f4a5b6-7c8d-4e9f-a0b1-c2d3e4f5a6b7',
  customerId: '3f2b8c1e-7a4d-4e9b-9c6f-1d2e3a4b5c6d',
  reason: 'CUSTOMER_REQUESTED',
  cancelledAt: '2026-09-12T20:10:05Z',
};

await client.publish('OrderCancelled', event);
```

## 2. Publish a cancellation after a payment failure

Capturing the payment failed after the order was created, so the Order Service cancels the order as compensation. The event carries only the required fields.

### Payload details

- `orderId` is the order that could not be paid for.
- `reason` is `PAYMENT_FAILED`.
- `customerId` is optional and omitted, so consumers must look the customer up by `orderId` if they need it.
- `cancelledAt` records when the compensation ran.

### Using this example

Use this to check that consumers handle an event without `customerId`, and that payment services do not try to refund money that was never taken.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderCancelled schema. The package names and publish methods are illustrative.

</Column>

## 3. Publish a cancellation because stock ran out

The warehouse finds that the last units of a product are damaged and cannot fulfil the order. The Order Service cancels it and tells downstream systems why.

### Payload details

- `orderId` is the order that cannot be fulfilled.
- `customerId` is included so the customer can be told and offered an alternative.
- `reason` is `OUT_OF_STOCK`.
- `cancelledAt` is the ISO-8601 UTC time of the cancellation.

### Using this example

Consumers should void or refund the payment, and reporting should count this as a stock problem rather than a customer choice.

The examples use a **fictional Acme Events SDK** to publish a payload matching the OrderCancelled schema. The package names and publish methods are illustrative.

</Column>
