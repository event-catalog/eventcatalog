## 1. Publish a registration with the customer's name

A shopper has signed up from the sign-up page with their full name. The Customer API publishes this event so downstream systems can onboard them, for example by sending a welcome email with a first-order discount.

### Payload details

- `eventId` is a unique UUID for this event, used by consumers to ignore duplicates.
- `occurredAt` is the ISO-8601 UTC time the customer registered.
- `customer.customerId` is the new customer's UUID, and `customer.email` is their sign-in address.
- `customer.name` is included because the customer supplied it at sign-up.
- `customer.status` is `ACTIVE`, the normal status for a newly registered account.

### Using this example

Use this to check that consumers create their own customer record keyed on `customer.customerId`, and that replaying the same `eventId` does not send a second welcome email.

The examples use a **fictional Acme Events SDK** to publish a payload matching the CustomerRegistered schema. The package names and publish methods are illustrative.

</Column>

```typescript publish-customer-registered.ts
import { EventsClient } from '@acme/events';
import type { CustomerRegistered } from './schemas/customer-registered';

const client = new EventsClient({
  apiKey: process.env.ACME_API_KEY!,
});

const event: CustomerRegistered = {
  eventId: '5e7d1a90-2c4b-4f3e-8a6d-1b9c0e2f4a57',
  occurredAt: '2026-03-14T10:22:05Z',
  customer: {
    customerId: '3f2b8c1e-7a4d-4e9b-9c21-5d8e6f0a1b2c',
    email: 'amelia.hart@example.com',
    name: 'Amelia Hart',
    status: 'ACTIVE',
  },
};

await client.publish('CustomerRegistered', event);
```

        "name", "Amelia Hart",
        "status", "ACTIVE"
      )
    );

    client.publish("CustomerRegistered", event);
  }
}

## 2. Publish a registration without a name

A shopper registered at checkout with only an email address and password, so the event carries no name. Consumers must handle this case, for example by greeting the customer without a first name.

### Payload details

- `eventId` and `occurredAt` identify this event and when the registration happened.
- `customer` contains only the required fields: `customerId`, `email` and `status`.
- `customer.name` is omitted because the customer did not provide one.
- `customer.status` is `ACTIVE`.

### Using this example

Use this to check that consumers do not fail when `customer.name` is missing, and that any welcome email falls back to a generic greeting.

The examples use a **fictional Acme Events SDK** to publish a payload matching the CustomerRegistered schema. The package names and publish methods are illustrative.

</Column>
